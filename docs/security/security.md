# 安全文档

---

## 1. 认证机制

### 登录认证

| 项目 | 方案 |
|------|------|
| 认证方式 | JWT (Access Token + Refresh Token) |
| 传输方式 | HTTPS + Authorization Header |
| Token 存储 | 前端：HttpOnly Cookie（推荐）或内存存储 |
| Token 有效期 | Access Token 2h，Refresh Token 7d |
| 密码存储 | bcrypt / argon2 哈希，禁止明文 |

### Token 刷新流程

```
Access Token 过期 → 使用 Refresh Token 获取新 Access Token
Refresh Token 过期 → 要求用户重新登录
```

## 2. 授权模型

### RBAC 角色权限

| 角色 | 权限范围 |
|------|----------|
| SUPER_ADMIN | 全部权限（用户管理、系统配置、数据查看） |
| ADMIN | 管理后台（内容管理、数据查看） |
| EDITOR | 内容新增/编辑/删除 |
| USER | 个人信息管理、基础功能使用 |
| GUEST | 仅可访问公开接口 |

### 权限校验层级

1. **路由中间件**：验证登录态 + 基本角色
2. **接口中间件**：细粒度权限校验
3. **数据权限**：按所属组织/用户过滤数据

## 3. 数据安全

### 敏感数据保护

| 数据类型 | 保护措施 |
|----------|----------|
| 密码 | bcrypt/argon2 哈希存储，不可逆 |
| 手机号 | AES 加密存储，日志中脱敏 |
| 邮箱 | AES 加密存储 |
| 身份证号 | AES 加密存储，日志中绝不出现 |
| 银行卡号 | 仅存储后四位 + Token 化 |
| Token/密钥 | 环境变量注入，不写入代码/日志 |

### 数据脱敏

日志输出规则：
```
手机号：138****1234
邮箱：u***@example.com
身份证：330***********1234
Token：不记录
密码字段：不记录
```

### SQL 注入防护

- 100% 使用参数化查询 / ORM，禁止字符串拼接 SQL
- 代码审查重点检查 `raw query` 使用

## 4. 接口安全

### 通用防护

| 措施 | 说明 |
|------|------|
| HTTPS | 全站强制 HTTPS，HSTS 头 |
| CORS | 仅允许白名单域名跨域 |
| CSP | Content-Security-Policy 头，防 XSS |
| 请求限流 | 基于 IP + 用户 ID + 接口 多维度限流 |
| 请求大小限制 | Body 限制防止大 payload 攻击 |

### 敏感接口加固

| 接口 | 附加措施 |
|------|----------|
| 登录 | 图形验证码 + 失败次数限流 + IP 黑名单 |
| 注册 | 图形验证码 + 手机/邮箱验证码 |
| 密码重置 | 验证码 + 临时 Token + 限流 |
| 支付回调 | 签名验证 + 来源 IP 校验 |
| 批量操作 | 需要二次确认 |

### 接口限流策略

| 接口类型 | 限流策略 |
|----------|----------|
| 登录 | 同一 IP 每分钟 10 次，同一账号每分钟 5 次 |
| 发送验证码 | 同一手机/邮箱每分钟 1 次，每小时 5 次 |
| 通用 API | 同一用户每秒 100 次 |
| 静态文件 | 不限制 |

## 5. 前端安全

| 措施 | 说明 |
|------|------|
| XSS 防护 | React/Vue 默认转义 + CSP 头 + 输入过滤 |
| CSRF 防护 | SameSite Cookie + CSRF Token |
| 敏感信息不暴露 | 控制台不输出敏感数据，生产关闭 debug 工具 |
| 依赖检查 | `npm audit` 定期扫描，修复已知漏洞 |
| Iframe 防护 | X-Frame-Options: DENY |

---

## 6. 基础设施安全

| 措施 | 说明 |
|------|------|
| 服务器加固 | 最小权限原则，关闭非必要端口 |
| SSH | 密钥登录，禁用密码登录，非标准端口 |
| 防火墙 | 仅开放 80/443 端口，内网服务绑定 127.0.0.1 |
| 数据库 | 白名单 IP 访问，内网不通公网 |
| Redis | 密码认证，bind 127.0.0.1 |
| 证书管理 | 使用 Let's Encrypt / 云服务自动续期 |
| Docker | 不使用 root 用户运行容器 |

## 8. 安全事件响应

### 事件等级

| 等级 | 定义 | 响应时间 |
|------|------|----------|
| P0 严重 | 数据泄露、资金损失、系统被入侵 | 15 分钟内响应 |
| P1 高危 | 核心功能漏洞被利用 | 1 小时内响应 |
| P2 中危 | 非核心功能漏洞 | 24 小时内响应 |
| P3 低危 | 安全配置问题 | 1 周内修复 |

### 响应流程

1. **发现** - 监控告警 / 漏洞报告 / 渗透测试
2. **研判** - 确认事件等级和影响范围
3. **止血** - 暂时摘除受影响服务流量、封禁攻击源
4. **修复** - 修复漏洞并验证
5. **复盘** - 事件复盘，更新安全规则

## 9. 安全检查清单

- [ ] 所有 API 强制 HTTPS
- [ ] 密码使用 bcrypt/argon2 哈希存储
- [ ] 敏感字段已加密存储

- [ ] 上传文件有类型和大小校验
- [ ] SQL 查询全部使用参数化查询
- [ ] 接口有合理的限流策略
- [ ] 登录接口有验证码和失败次数限制
- [ ] CORS 配置仅允许白名单域名
- [ ] 前端不暴露调试工具到生产环境
- [ ] 第三方依赖无已知高危漏洞
- [ ] 容器不以 root 用户运行
